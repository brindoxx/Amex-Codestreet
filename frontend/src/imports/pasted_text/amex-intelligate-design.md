Project Title: AmEx Intelligate - End-to-End Servicing Agent
Design Style/Theme: Premium, minimalist, corporate-banking, highly trustworthy. Clean lines, ample whitespace, utilizing a primary "AmEx Blue" color palette with crisp typography. Avoid cluttered dashboards; prioritize a conversational, chat-first UI.  1. Global Components & Layout ShellThe Dashboard Shell (Persistent across most screens):Left Collapsible Sidebar: Include distinct navigation icons and labels for: "New Conversation", "Conversation History", "Audit Log Ledger", "Settings", and "Member Profile".  Top Header: Include a crisp AmEx logo on the left. On the right, include a persistent, highly visible "Chat / Call Toggle" switch (a microphone icon and a keyboard icon) and a user profile thumbnail.  Main Stage (Center): The primary operating area where the chat/voice interface or the selected sidebar page lives.  2. Screen Requirements & User FlowsScreen 1: Authentication & Landing ViewVisuals: The main stage is centered and un-cluttered.Elements: A large, welcoming text heading: "How can I help you today, Riya?".  Input Box: A prominently centered text input bar containing a microphone icon inside the right edge.  Quick Action Chips: Below the input bar, place three clean suggestion buttons: "Reverse a fee", "Limit increase", and "Replace card".  Screen 2: Chat Flow A - Credit Limit Increase (With Inline Security)State 1 (User Request): A chat bubble from the right (user) saying, "I need to increase my credit limit to $12,000."  State 2 (Policy Check Indicator): A subtle, animated loading state or typing indicator from the system that says: “Checking tier eligibility & policies…”.  State 3 (Agent Response & Security Gate): A chat bubble from the left (Agent) stating: "You are eligible for a limit increase up to $10,000 based on your current tier cap. To execute this, please verify your identity."  State 4 (Inline Authentication Widget): Directly inside the chat flow, render a secure input widget with:A field for "Last 4 digits of Card".A field for "4-digit CVV".A button to "Send OTP".A final input field for a 6-digit OTP sent to the registered mobile number.State 5 (Confirmation & Audit Stamp): A final system message: "Success. Your new limit of $10,000 is active." Beneath this, an embedded UI badge/stamp that reads: "Logged as LIM-2291. Hash: 0x8F4B... View Audit Log".  Screen 3: Chat Flow B - Card Replacement (Escalation to Voice)State 1 (High-Urgency Request): User bubble: "I lost my card on the train."State 2 (Routing Behavior): System recognizes the "lost/stolen" flag.  State 3 (Voice Nudge): The system bubble replies: "I will lock your card immediately to prevent unauthorized charges. Since this is urgent, would you prefer to complete the replacement over a voice call?" Include two large action buttons in the chat: "Switch to Call" (highlighted) and "Continue in Chat".  State 4 (Active Call State): If "Switch to Call" is clicked, the UI morphs. The chat text fades back slightly, and a large, sleek, glowing voice-activity visualizer appears in the center of the screen to indicate natural conversational pacing and active listening.  Screen 4: Chat Flow C - Fee Reversal (Policy Denial)State 1: User asks to reverse a late fee.State 2: System checks the 90-day waiver policy.  State 3: System bubble: "I see we waived a fee for you 45 days ago. Our policy allows one waiver per 90 days, so I cannot reverse this charge today. Your next eligible date is [Date].". Included is the standard cryptographic audit badge.  Screen 5: The Verifiable Audit Log Ledger PageVisuals: This page replaces the main chat stage when selected from the sidebar. It should look highly technical, secure, and tabular.Elements: A wide data table.  Columns Required:TimestampAction ID (e.g., FEE-883, LIM-2291)Action Type (Limit, Fee, Replace)  Policy Evaluated (e.g., "Tier Cap Exceeded", "90-day Waiver Cleared")Outcome (Approved / Partially Approved / Denied)SHA-256 Hash Chain (A truncated alphanumeric string like 8a9df2... with a "copy" icon).  Detail View: Show a side-drawer or pop-up modal for when a row is clicked, revealing the raw JSON payload of the tool call and the exact immutable log entry.  Screen 6: Human Escalation & Context Handoff ViewVisuals: This is the AmEx employee's view, entirely distinct from the customer view.Elements:Customer Profile Summary on the left (Name, Tier, Tenure).Context Summary Card (Center): A structured summary box, not a raw transcript. It should clearly list:  Intent: Credit Limit IncreaseSystem Action Taken: Denied by Agent.Reason: Requested amount ($50,000) exceeds maximum automated confidence threshold.  Customer Authentication: Verified (OTP passed).Below the summary, a collapsed view of the actual chat transcript that the human agent can expand if necessary.3. Prototyping Connections (How the pages link)Clicking the mic toggle on Screen 1 instantly morphs the input bar into the active voice state (Screen 3, State 4).Clicking "Limit Increase" on Screen 1 triggers the Chat Flow A sequence.Clicking the "View Audit Log" text in any chat confirmation badge automatically opens Screen 5 (Audit Log Ledger), highlighting the specific row of that transaction.Sidebar Navigation: Ensures the user can switch between an active conversation and their historical audit logs without losing the chat state.
